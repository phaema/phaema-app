How to use this programme

This programme tests every section of PHAEMA in about 12 working days, using the demonstration data in two fictional districts. Each test below is a set of instructions for a person to follow in PHAEMA: an ID, steps, the expected result and a Result column to fill in. Tests marked (IT) need someone who can type commands on the computer that runs PHAEMA.

Where to test. Either use the public test site at demo.phaema.co.uk, or install a private copy for your council with the installation guide in the code repository (deploy/README.md). On the public site, ask for sign-ins with Request a test account (the PHAEMA project sets them up), and note that all data is reset every 48 hours: run each section within a day, record results as you go, and do not rely on records surviving overnight. Tests that need an Administrator account, or that change other people's work (sections U, Y and Z), are best run on a private copy.

Test data. Load it with python manage.py load_demo_data --reset (an IT task). It holds 72 properties, 47 agreements, 56 cases, 22 repair jobs, 59 certificate requirements, 35 valuations and two service charge schedules. All names, addresses, numbers and documents are invented.

DistrictReferencesGood for testing
ExampletonDM-E01, DM-S01 to DM-S11Riverside Industrial Estate, Market Square shops, Town Hall, Enterprise Centre (leased in, sub-let), a confidential property, surplus school site
NorthfieldDM-N01 to DM-N12Business park, The Precinct shops, library and leisure centre (compliance), former bus depot (hazards, surplus), telecoms site, market hall (turnover rent), farm, Innovation Hub (leased in)

Agreements are DL-0001 to DL-0200 (Exampleton) and DL-0501 to DL-0531 (Northfield). Dates are set relative to the day you load the data, so reviews, breaks and certificates always fall due at a realistic mix of times. Reload before each test cycle so everyone starts from the same position.

Projects. Three fictional projects: PRJ-2026-001 (a development at Northfield Business Park), PRJ-2026-002 (a confidential depot site acquisition) and PRJ-2026-003 (a disposal of two surplus sites). Section PJ uses them.

Demonstration people. Surveyors Alex Morgan, Priya Shah, Owen Jones, Lena Chen and Rob Baker are supervised by Sam Hughes (Head of Estates); Jo Patel is a legal contributor. They cannot sign in. Use them to test assignment, approvals and My work, viewed as an administrator.

Test accounts. In Manage data, create one account per role for each tester, with a password: an Administrator, two Surveyors (one supervising the other), a Contributor and a Viewer. Give one Surveyor some properties as managing surveyor. Put every account in all five access areas to start with; section Z narrows them. Give every account its own email address. Administrators are asked to set up two-step sign-in the first time they sign in (test A9), so have an authenticator app ready on a phone. Tests A15 to A18 need single sign-on set up by IT against a Microsoft 365 (or other) test tenant; without one, run A14 only. Never use real people's details.

Before you start: switch on every module in Manage data, Module settings (rent ledger, service charges, maintenance, compliance, asset valuation). Some tests switch one off and back on.

Programme

Run the phases in order: later sections depend on the register, leases and cases working. Two testers can split each phase by section.

DaysPhaseTests
1Set-up and smoke test: load data, create accounts, sign in as each role, check every menu item opensA, B
2–3The register: properties, map, titles, parties, agreements, lease events and remindersC, D, E, F
4–5Casework: cases, approvals, heads of terms and 1954 Act, standards checks, document library, projectsG, H, I, J, PJ
6–7Income: rent ledger and service chargesK, L
8–9Buildings: maintenance, compliance and Golden Thread, asset valuationM, N, O
10Data in and out: reports, imports and exports, open data, API, change log, settingsP, Q, R, S
11Cross-cutting: accessibility, security and permissions, browsers and devices, performance, access areas and coverT, U, V, W, Z
12Hand over work (changes demo data, so run last and reset), retest fixed defects, run the automated suite, sign offY, X

Start when: the demo data loads without errors, every tester has their accounts, and the automated test suite passes (python3 -m pytest).

Finish when: every test has a result; no Critical or High defects are open; Medium defects have an agreed fix date or are accepted; the automated suite passes on the final build.

Recording results

In each test's Result column write P (pass), F (fail, with a defect number), B (blocked by another defect) or N/A (module not in use), plus your initials and the date.

SeverityMeaningExample
CriticalData lost or wrong, a security hole, or a whole section unusableA Viewer can edit a lease; a rent charge is posted twice
HighA main task cannot be done, with no workaroundCannot record a rent review outcome
MediumA task works but wrongly or awkwardly, with a workaroundA report total is missing; a filter ignores one option
LowWording, layout or cosmeticA typo; misaligned column

For each defect record the test ID, the page address, what you did, what you expected, what happened, a screenshot, and your browser. Raise it as an issue on GitHub (phaema/phaema-app) with the label testing, or in the defect log at the end of this document.
